# Services

## Overview

The Services directory in our Vue application contains a collection of functions that communicate with the back-end. These service functions are used to fetch, update, and manage data from the server. They work very well with Pinia stores, allowing us to store data and share it across components.

## What are Services?

Services are JavaScript modules that handle the communication between the front-end and the back-end of an application. They encapsulate the logic for making API calls and processing responses, providing a clean and organized way to manage data interactions.

### Benefits of Using Services

- **Separation of Concerns**: Services separate the data-fetching logic from the component logic, making the codebase more modular and maintainable.
- **Reusability**: Service functions can be reused across different components and stores, reducing code duplication.
- **Testability**: By isolating the API interaction logic, services can be easily tested in isolation.

## Usage

Services are used to fetch data from the back-end and then store that data in Pinia stores. This approach allows us to keep our components clean and focused on presentation logic.

### Example: Playlist Service

Here's an example of a service file for playlists. This service file contains functions to get playlist data from an endpoint.

```javascript
// services/playlistService.js
import axios from 'axios';

const API_BASE_URL = 'https://api.example.com';

export const getPlaylists = async () => {
  try {
    const response = await axios.get(`${API_BASE_URL}/playlists`);
    return response.data;
  } catch (error) {
    console.error('Error fetching playlists:', error);
    throw error;
  }
};

export const getPlaylistById = async (id) => {
  try {
    const response = await axios.get(`${API_BASE_URL}/playlists/${id}`);
    return response.data;
  } catch (error) {
    console.error('Error fetching playlist:', error);
    throw error;
  }
};
```

## Integrating Services with Pinia Stores
Pinia stores can call service functions to fetch data from the back-end and store it in the state. This data can then be shared across different components.

### Example: Using Playlist Service in a Pinia Store

```javascript
// stores/playlistStore.js
import { defineStore } from 'pinia';
import { getPlaylists, getPlaylistById } from '@/services/playlistService';

export const usePlaylistStore = defineStore('playlist', {
  state: () => {
    return {
      playlists: [],
      activePlaylist: {},
      loadingPlaylists: false,
      loadingActivePlaylist: false,
      // Add other state properties here
    };
  },
  actions: {
    async fetchPlaylists() {
      this.loadingPlaylists = true;
      try {
        this.playlists = await getPlaylists();
      } catch (error) {
        console.error('Error fetching playlists:', error);
      } finally {
        this.loadingPlaylists = false;
      }
    },
    async fetchPlaylistById(id) {
      this.loadingActivePlaylist = true;
      try {
        this.activePlaylist = await getPlaylistById(id);
      } catch (error) {
        console.error('Error fetching playlist:', error);
      } finally {
        this.loadingActivePlaylist = false;
      }
    },
    // Add other actions here
  }
});
```

### Example Usage in a Vue Component
```html
<template>
  <div>
    <h2>Playlists</h2>
    <ul>
      <li v-for="playlist in playlists" :key="playlist.id">{{ playlist.title }}</li>
    </ul>
  </div>
</template>

<script setup>
import { onMounted } from 'vue';
import { usePlaylistStore } from '@/stores/playlistStore';

const playlistStore = usePlaylistStore();

onMounted(() => {
  playlistStore.fetchPlaylists();
});

const { playlists } = playlistStore;
</script>
```

## Conclusion

The Services directory is an essential part of our Vue application, handling communication with the back-end and working seamlessly with Pinia stores. By using services, we can keep our data-fetching logic organized, reusable, and testable, while leveraging Pinia stores to manage and share state across components.
