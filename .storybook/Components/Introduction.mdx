# Introduction to Vue Components at Musora

Welcome to the Musora front-end development documentation. This document provides an overview of our Vue components, their structure, and how we use aliases for efficient development.

## Atomic Design Approach

At Musora, we follow the **atomic design** methodology to build our front-end experience. This approach breaks down the interface into fundamental building blocks, which can be combined to create more complex components and pages. Our component structure is categorized into **Units**, **Collections**, and **Pages**.

### Units

Units are the smallest reusable components in our design system. They represent the basic building blocks, such as buttons, inputs, and icons. These components are designed to be highly reusable and composable.

### Collections

Collections are composed of multiple Unit components. They represent more complex elements of the interface, such as forms, menus, and cards. Collections are used to build larger interface sections by combining several Unit components.

### Pages

Pages are the top-level components that represent entire views or screens in the application. They are composed of multiple Collections and Units. Pages form the overall layout and structure of the user interface.

## Directory Structure

Our Vue component directory is organized as follows:

```
src/
|-- components/
| |-- Units/
| | |-- Button.vue
| | |-- Input.vue
| |
| |-- Collections/
| | |-- Form.vue
| | |-- Card.vue
| |
| |-- Pages/
| |-- HomePage.vue
| |-- ProfilePage.vue
```

## Aliases

To simplify the import paths and improve the maintainability of our codebase, we use aliases for our component directories. This allows us to reference components using a short and clear path.

Here are the aliases we use:

- **Units**: `@units`
- **Collections**: `@collections`
- **Pages**: `@pages`

### Usage

You can import components using these aliases in your Vue files. For example:

```js
<template>
  <div>
    <Button />
    <Form />
    <HomePage />
  </div>
</template>

<script>
    import Button from '@units/Button.vue';
    import Form from '@collections/Form.vue';
    import HomePage from '@pages/HomePage.vue';

    export default {
        components: {
            Button,
            Form,
            HomePage,
        },
    };
</script>
```

Using aliases helps to keep our import statements clean and makes it easier to manage the component structure as the project grows.

## Conclusion

By following the atomic design methodology and using aliases for our component directories, we can build a scalable and maintainable front-end architecture. This approach allows us to create a consistent and reusable set of components that can be efficiently managed and extended.

Feel free to explore the documentation for more details on individual components and their usage.
